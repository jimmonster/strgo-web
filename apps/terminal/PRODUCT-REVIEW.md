## 开发前代码核查

- `image_service/app.py` 已使用 SQLite 会话、7 天 `SESSION_AGE`、用户 `member/admin` 角色、登录限流、CSRF、改密撤销会话；当前 Cookie 的 `Path=/api/image/` 不能直接供 `/terminal` 使用，需共享 Cookie 与旧登录迁移。
- 生图 `/session` 会读取配置、额度与存储状态，不适合作为终端身份强依赖；应提供只读取账户会话的轻量核验接口。
- `apps/terminal/src/web.rs` 目前是终端独立访问口令及进程内 8 小时会话；不能满足共享账号和重启保留登录，必须替换身份来源。
- `apps/terminal/web/app.js` 目前仅有一组全局 socket、xterm、草稿和聊天状态；多窗口必须落到独立状态对象，不能只切换列表标题。
- 现有聊天输出有约 120 条气泡、300 行与 48,000 字符的裁剪，原始终端有 4,000 行回滚；复制／导出需准确标明当前保留范围。
- 现有容器以 UID 10001、只读根、内存／CPU／进程限制运行 SSH；工作目录是临时 tmpfs，尚无持久账号工作区。现有镜像入口是 SSH，新增本地 shell 需显式覆盖入口。
- 现有 Docker bridge 仅关闭容器互访，SSH broker 的目标地址验证不能限制用户在新 shell 内任意联网；默认本地工作区必须无网络。
- 现有服务级 SSH 私钥会挂载到连接容器；扩展给普通账号后必须限制为管理员 SSH 场景，普通工作区及成员均不得继承。

## 必须修订点与处理

以下修订已写入需求 v1.1，属于开发约束，无需为这些已获授权的范围再次征求确认。

1. 明确共享会话范围、旧 Cookie 迁移不延长有效期、双入口统一退出与 30 秒撤销时限。
2. 明确首次登录自动打开工作区、刷新恢复待连接、故障后保留登录并可重试，区分窗口数与后端并发数。
3. 明确文件持久与进程持久的区别；默认 1 小时时限、非敏感元数据恢复和密码字段清空。
4. 明确默认基础 shell 无网络、无 root／sudo 承诺；既有 SSH 保留为高级入口并保持地址验证。
5. 明确聊天裁剪和导出范围、原始终端多行粘贴确认、复制不触发 Ctrl+C、拆包密码回显脱敏。
6. 明确持久卷的容量治理与限制，不把 Docker 命名卷误称为具有每账号磁盘硬配额。
7. 明确完成口径：自动测试、浏览器核查、产品复核与真实环境验证分别记录；不得把本地模拟当作线上成功。

### 实际缺陷闭环

| 级别 | 发现与影响 | 修复和复核 |
| --- | --- | --- |

| P2 | 400 列终端输出 60,000 字符但未达 300 行时，仅做 48,000 字符裁剪，无省略提示 | 已修复：行裁剪、字符裁剪分别判断，任一发生显示提示。相同 probe 保留 48,010 字符（含提示），省略提示存在 |
| P2 | 首屏账号检查与子页身份请求没有超时，接口持续不返回时一直等待 | 已修复并核对：两处均设置 8 秒 AbortController，超时显示可操作提示，释放登录按钮或连接重试 |

| P2 | 本地工作区退出沿用「SSH 已退出」，容易误解操作对象 | 已修复并核对：按工作区／SSH 分流退出文案 |
