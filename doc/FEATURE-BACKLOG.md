# 功能缺口与执行清单

更新：2026-10-23（Asia/Shanghai）。基准：`e1f0f5c`。本清单依据当前源码、[整仓审查](PROJECT-REVIEW.md)、各模块验收及用户追加需求维护；历史报告中的环境阻断不能直接当作现状。状态随实际验证更新。

## 执行规则

P0 为紧急泄露或广泛破坏；P1 为账号治理、数据保存、关键链路与资源冲突；P2 为集成可靠性、可发现性和一般功能；P3 为可选视觉增强。先完成 P1 仓库内开发，再完成支撑交付的 P2。外部验收与代码开发分开：无需真实设备即可补齐代码，实际设备效果仍保留验收项。

用户授权：补齐发现的缺失功能及必要需求、增加全站统一后台（账号与邀请码、权限额度、社区、AI、任务、存储摘要），验证后提交 GitHub。该授权不包含生产发布、调用收费模型或编造作者材料。

用户追加交付规则：每完善一个需求，独立验证、提交并推送GitHub，不等待整批完成。工作分支为 `codex/feature-completion-admin`；本轮F01–F13已完成，提交对应关系及验证见下文。外部事项E01–E08保留明确处理条件。

## 新需求边界

后台需要补充审计、最后管理员保护、禁止自我停用、撤销会话、并发操作校验、分页与异常反馈，均属于账号治理必要条件。后台不公开成员密钥、密码散列、私人对话/歌词/音频正文。AI 精细配置复用既有 `/admin/ai/`；管理员也须通过既有 TOTP 和显式模块授权。

完成证据必须包含真实执行的命令/结果及对应范围；新发现的实际缺陷追加到本表，不凭测试通过宣称线上已部署。
